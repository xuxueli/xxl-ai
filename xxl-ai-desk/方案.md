## 一、需求相关

| 项 | 结论 |
|---|---|

## 二、总体架构（当前实现）

```
┌────────────────────────────────────────────────────────────┐
│ Renderer（Vue3 + Element Plus，无 Node 直连）               │
│  会话列表 · 对话流 · Composer · 设置（通用 / 供应商）        │
└───────────────▲────────────────────────────────────────────┘
                │ contextBridge（preload 暴露 window.desk.*）
┌───────────────┴────────────────────────────────────────────┐
│ Main（Electron 主进程，Node / CJS）                          │
│  窗口/生命周期 · IPC 网关 · SQLite(Drizzle) 持久化           │
│  Agent Host：Pi 运行时封装，事件经 IPC 推送 · safeStorage    │
└───────────────┬────────────────────────────────────────────┘
                │ 主进程内嵌 SDK：动态 import()（Pi 为 ESM）
┌───────────────▼────────────────────────────────────────────┐
│ Pi Runtime（@earendil-works/pi-agent-core + pi-ai，ESM）     │
│  多供应商 LLM · Agent 循环 · 工具调用 · 事件流 · 会话状态     │
└────────────────────────────────────────────────────────────┘
```

- **安全**：`contextIsolation: true`、`nodeIntegration: false`；`sandbox: false`（preload 需要，已在模板中权衡）。渲染层仅经 preload 白名单 IPC 访问能力。
- **Pi 落位**：当前**直接内嵌主进程**（每次会话构建 Pi `Agent`，事件经 IPC 推送）。后续如需隔离，可平滑迁移到 `utilityProcess` / `child_process`（见 §十二）。
- **数据流**：UI 输入 → IPC → Agent Host → Pi 事件流（思考/token/工具调用）→ IPC 推送 → UI 流式渲染 → 完成后以 Agent 完整上下文落 SQLite。

## 三、技术选型（已确认）

| 维度 | 结论 | 一句话理由 |
|---|---|---|
| 构建脚手架 | **electron-vite 5** | 三进程统一构建、Vue3+TS 无缝、HMR 好 |
| 包管理器 | **npm** | 与 `xxl-ai-ui` 一致 |
| 前端框架 | **Vue 3.5 + TypeScript** | 与平台一致 |
| UI 组件库 | **Element Plus 2.14** + SCSS 设计令牌 | 与 `xxl-ai-ui` 一致；不引入 Tailwind/shadcn（放弃最初推荐，以一致性优先） |
| 状态/路由 | **Pinia 4 + vue-router 5（hash）** | 与平台一致；hash 兼容 `file://` |
| Agent 运行时 | **Pi（`pi-ai` + `pi-agent-core`）主进程内嵌** | 类型贯通、调试最简；UI/工具完全自控 |
| 本地存储 | **better-sqlite3 13 + Drizzle ORM 0.45** | 单文件、同步快；N-API 预编译兼容 Electron |
| 密钥安全 | **Electron `safeStorage`** | 系统钥匙串加密，`enc:v1:` 前缀标识 |
| 内容渲染 | **markdown-it + DOMPurify** | 轻量安全；Shiki/KaTeX/Mermaid 依赖已装、暂未接入 |
| i18n | **vue-i18n 11（zh/en）** | 与平台一致 |
| 日志 | **electron-log 5** | 主进程日志 |
| 打包/更新 | **electron-builder 26 + electron-updater 6** | 三平台产物；更新渠道待配 |
| 本地知识库/记忆 | **暂缓**（M4 评估 `sqlite-vec`） | 首版聚焦对话闭环 |

> 备选方案（Forge/Quasar、Naive/Arco、child_process RPC、LanceDB 等）此处从略，历史选型过程见本文件 git 历史或个人记录。

## 九、实现总结（M1 + M2）

### 9.1 启动与运行
```bash
cd xxl-ai-desk
npm install
node node_modules/electron/install.js       # 若安装时用了 --ignore-scripts，需补下载 Electron
npx electron-builder install-app-deps       # 重建 better-sqlite3（N-API，实际直接命中预编译）
npm run dev                                  # 开发（HMR）
npm run type-check | npm run build | npm run pack | npm run build:mac|win|linux
```
主进程启动顺序：`app.whenReady → initDatabase → ensureSeedProviders → registerIpc → createWindow`；单实例锁防多开争库。

### 9.2 IPC 频道（`src/shared/ipc.ts`）
- `desk:app:info`；`desk:app:set-data-dir|select-data-dir|open-data-dir|relaunch`（运行时数据目录）
- `desk:settings:get|save`
- `desk:provider:list|save|remove|remote-models`
- `desk:session:list|create|update|rename|remove|messages|clear`
- `desk:chat:send|abort`（invoke）；`desk:chat:event`（主→渲染推送）

### 9.3 对话主流程
1. UI `chatStore.send(text)` → `api.chat.send({sessionId, text})`
2. `ipc chat:send`：取会话 → 设置 → 供应商（DTO→runtime，含 headers）→ 读取历史消息（用 `data` JSON 还原 Pi 消息）
3. `getAgent({sessionId, provider, modelId, systemPrompt, messages})`：
   - `buildModels([{...provider, sessionId}])`（`pi-ai` createModels/createProvider + `openAICompletionsApi`）
   - `new Agent({ initialState:{systemPrompt, model, tools}, streamFn: models.streamSimple.bind(models) })`
   - `agent.state.messages = 历史`
4. `runPrompt(agent, text, sink)`：`agent.prompt(text)`；订阅事件映射：
   - `message_update.text_delta` → `delta`；`thinking_delta` → `thinking`
   - `tool_execution_start/end` → `tool_start/tool_end`
   - 结束后按最后 assistant `stopReason` 判定 `done` / `error`
5. 完成后 `replaceMessages(sessionId, agent.state.messages)` 全量落库；首条消息自动作会话标题。

### 9.4 供应商与请求Header（关键，已修复 `x-opencode-session`）
- 表 `desk_provider` 字段：`name / base_url / api_key(加密) / headers(JSON对象) / models(JSON数组) / enabled / sort`。
- `{session}` 占位符：`buildRequestHeaders()` 将 value 中 `{session}` 替换为**当前会话ID**，空会话则跳过该头（对齐平台 `LlmModelFactory`）。
- **挂载位置**：Pi 请求头合并顺序为 `provider auth headers → model.headers → options.headers → transformHeaders`；`provider.headers` 不参与 `applyAuth`，因此**自定义头挂到每个 `model.headers`**（已验证 `models.getAuth()` 解析出 `{"x-opencode-session":"<sessionId>"}`）。
- **BaseURL 归一化**：结尾去斜杠；裸地址自动补 `/v1`（Pi 把 baseURL 交给 OpenAI SDK，SDK 追加 `/chat/completions`）。
- **预置供应商**（首次启动自动播种，表为空时）：OpenCodeGo（`headers={"x-opencode-session":"{session}"}`）、Ollama、Deepseek、智谱GLM；并默认选中首个。

### 9.5 持久化
- `desk_session(id,title,provider_id,model_id,system_prompt,add_time,update_time)`
- `desk_message(id,session_id,seq,role,content,data,add_time)`，`data` 为 Agent 原始消息 JSON
- `desk_setting(key,value)`
- **迁移**：`ensureColumn()` 用 `PRAGMA table_info` 检测并 `ALTER TABLE` 补列（SQLite 无 `ADD COLUMN IF NOT EXISTS`）——`headers` 列即由此补齐。
- **运行时数据目录**：默认 `app.getPath('userData')/xxl-ai-desk.sqlite`；可在「通用设置 → 数据目录」查看/浏览/打开/修改（`storageService.ts` 写入 `userData/desk-config.json`，配置独立于库本身避免自引用），修改后需重启应用生效。
- **密钥**：`security.ts` 用 `safeStorage` 加密，`enc:v1:` 前缀；解密兼容历史明文。

## 十、关键实现细节与踩坑（下次务必注意）

1. **Pi 包 scope**：用 `@earendil-works/pi-*`（1.0.0），不要用已废弃的 `@mariozechner/pi-*`。
2. **Pi 是 ESM-only，主进程是 CJS**：不能在主进程**静态** `import` Pi 的运行时值；必须 `await import('@earendil-works/pi-ai')`（`externalizeDepsPlugin` + Rollup `dynamicImportInCjs` 会保留原生 `import()`，运行时正常）。类型可用 `import type`。
3. **自定义请求头必须挂 `model.headers`**：Pi 的 `provider.headers` 不经过 `applyAuth`，只有 `model.headers` 与 auth 返回的 headers 会合并进请求。
4. **vue-i18n 花括号陷阱**：i18n 文案里出现字面 `{...}` 会被当插值占位符，触发 `SyntaxError`（本项目曾因 `{session}` 导致设置弹窗渲染失败、表现为「点编辑没反应」）。**JSON 示例等含花括号内容不要放进 i18n**，改用模板静态常量渲染。
5. **better-sqlite3 与 Electron**：N-API 预编译（`prebuilds/`）跨 Node/Electron 稳定，`electron-builder install-app-deps` 即可；若 `npm install --ignore-scripts`，需手动补 `node node_modules/electron/install.js`。
6. **safeStorage 依赖 app ready**：加密函数在 `whenReady` 之后调用。
7. **窗口/主题**：窗口 `backgroundColor:#ffffff` 且默认浅色；`applyTheme()` 通过 `html.dark` 切换 Element Plus 深色。
8. **CSP**：`index.html` 的 `connect-src` 放行 `ws://localhost:* http://localhost:*`，否则 dev HMR 被拦。
9. **单实例锁**：避免多开导致 SQLite 竞争。

## 十二、下次开发指引（M3 起）

### 12.1 建议顺序与落点
1. **M3a MCP 管理**：
   - 主进程：`src/main/services/mcpService.ts`（CRUD，配置 JSON：远程 `{transport,url,headers}` / 本地 `{transport,command,args,env,cwd}`）；运行时在 `src/main/agent/` 新增 `mcp/`（连接/列举/调用），或复用 Pi 的 MCP 扩展。
   - IPC：新增 `desk:mcp:*` 频道；前端新增 `modules/mcp/`（列表 + 连接测试 + 工具明细弹窗）。
2. **M3b SKILL 管理**：
   - 采用 Pi 原生 `SKILL.md` + 文件树约定；主进程负责物化到本地目录并注入 Agent（工具或系统提示），前端 `modules/skill/` 提供导入/列表。
